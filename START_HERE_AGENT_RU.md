# Быстрый старт ИИ-агента

Прочитай этот файл один раз. После него должно быть понятно, куда идти и что
проверять.

## Что это за проект

Site Control Kit связывает ИИ-агента с настоящим браузером:

```text
агент -> CLI или HTTP -> хаб -> очередь -> расширение -> вкладка
```

Хаб — единственный источник правды. Расширение только исполняет аренду команды
и возвращает результат.

## Что прочитать

1. Корневой `AGENTS.md`.
2. `docs/PROJECT_STATUS_RU.md` — что реально готово сейчас.
3. `docs/ARCHITECTURE.md` — границы компонентов.
4. `docs/API.md` — если меняешь протокол или команды.
5. `AGENTS.md` внутри рабочей папки.

Не читай старые контрольные точки подряд. Они нужны только для расследования
истории.

## Как начать любую задачу

```bash
git status --short --branch
git log --oneline -n 15
PYTHONPATH="$PWD" python3 -m unittest discover -s tests -p 'test_*.py'
```

Определи подсистему:

- HTTP и auth — `webcontrol/server.py`;
- доставка и ожидание команды — `webcontrol/services.py`;
- транзакционные переходы и сессии — `webcontrol/store.py`;
- вкладки, iframe, CDP — `extension/background.js`;
- DOM, локаторы, ожидания — `extension/agent_dom.js` и `content.js`;
- короткие команды — `webcontrol/cli.py`;
- Telegram — `scripts/telegram_*`, отдельно от браузерного ядра;
- упаковка — `packaging/`.

## Первый браузерный сценарий

Проверь живой контур:

```bash
sitectl browser status
sitectl browser tabs
```

Сделай снимок:

```bash
sitectl browser snapshot
```

Нажми элемент:

```bash
sitectl browser smart-click --role button --name "Сохранить" --exact
```

Введи текст:

```bash
sitectl browser set-text --label "Имя" "Анна"
```

Для долгого сценария сначала создай сессию и заблокируй вкладку. Без этого два
агента могут работать с одним браузером только в старом режиме совместимости.

## Правила, которые экономят время

- Не повторяй клик вслепую после неопределённой ошибки.
- Для чтения используй `safe_retry`.
- Для ввода — `retry_if_not_started`.
- Для отправки формы или другого опасного действия — `never_retry` и проверку
  результата.
- Сначала `snapshot`, потом действие по `ref` или роли.
- Не выбирай первый элемент при неоднозначности.
- Всегда задавай точные `client_id` и `tab_id` в сессии.
- После сна или перезагрузки расширения снова проверь статус.

## Как добавить новую браузерную возможность

Пример: нужно добавить выбор элемента списка.

1. Опиши payload и результат в `docs/API.md`.
2. Добавь классификацию повтора в `webcontrol/protocol.py`.
3. Реализуй DOM‑часть через общий `agent_dom.js`.
4. Добавь короткую CLI‑команду, если она нужна агенту часто.
5. Положи минимальный JSON в `examples/`.
6. Добавь модульный тест.
7. Добавь сценарий в `scripts/browser_e2e.py`, если команда проходит через
   настоящий браузер.
8. Обнови `docs/PROJECT_STATUS_RU.md`.

## Частые вопросы

### Почему команда зависла в `queued`?

Нет онлайн‑клиента, выбрана неверная цель или расширение не держит долгий
запрос к хабу.
Проверь `browser status`, `clients` и `tabs`.

### Почему старая команда получила `stale_lease`?

Её аренда уже истекла и выдана новая. Старый результат нельзя принимать:
иначе он перезапишет актуальный.

### Почему клик попал в `dead_letter`?

Расширение успело сообщить `running`, но результат потерялся. Повтор может
нажать кнопку второй раз, поэтому нужно проверить страницу вручную или отдельной
командой чтения.

### Почему `ref` перестал работать?

Страница или фрейм сменились. Возьми новый снимок. Автовосстановление допустимо
только при единственном уверенном кандидате.

### Где искать доказательства ошибки?

В `artifact_dir` сессии: `commands.jsonl`, `events.jsonl`, `errors.jsonl` и
каталог failure bundle.

## Когда задача закончена

Запусти:

```bash
PYTHONPATH="$PWD" python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/check_docs.py
python3 scripts/check_repository.py --base origin/main
git diff --check
```

Для изменённого браузерного контура нужен реальный E2E. Запиши результат и
остаточный риск в `docs/PROJECT_STATUS_RU.md`, затем сделай один или несколько
понятных русских коммитов.
