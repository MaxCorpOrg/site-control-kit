# Правила для ИИ-агентов

## Назначение

Эти правила защищают совместимость браузерного ядра, отделяют подсистемы и
задают единый порядок проверки.

## Сначала

1. Прочитайте `START_HERE_AGENT_RU.md`.
2. Прочитайте `docs/PROJECT_STATUS_RU.md`.
3. Выполните `git status --short --branch` и `git log --oneline -n 15`.
4. Прочитайте `AGENTS.md` рабочей папки.

Не считайте проект пустым и не переносите старую ветку целиком.

## Границы подсистем

- браузерное ядро: `webcontrol/`, `extension/`, browser‑тесты и примеры;
- Telegram и GTK: `scripts/telegram_*` и `scripts/telegram_gui/`;
- упаковка: `packaging/`;
- документация: корневые русские руководства и `docs/`.

Браузерное ядро, документация и Telegram идут отдельными PR.

## Неприкосновенные правила

- хаб — единственный источник правды;
- токен не ослаблять и не передавать через URL/JSON;
- старый `lease_token` не принимается;
- опасное действие после `running` не повторяется вслепую;
- сессионная команда использует точный клиент, вкладку и блокировку;
- совместимые CSS‑команды не удалять без миграции;
- протокол менять только с версией, API, примером и тестом;
- не коммитить runtime, профиль, секрет, персональные данные или бинарную
  сборку.

## Обязательные проверки

```bash
PYTHONPATH="$PWD" python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/check_docs.py
python3 scripts/check_repository.py --base origin/main
git diff --check
```

Для Python также `py_compile`, для shell — `bash -n`, для расширения —
`node --check` и Chrome E2E.

## Документация

Вся пользовательская документация пишется по‑русски. Нужный английский термин
объясняется через `docs/TERMS_RU.md`.

Источники правды:

- API — `docs/API.md`;
- архитектура — `docs/ARCHITECTURE.md`;
- безопасность — `docs/SECURITY.md`;
- состояние — `docs/PROJECT_STATUS_RU.md`;
- план — `docs/ROADMAP_RU.md`.

Не копируйте большие разделы между файлами. Ставьте ссылку на главный документ.

## Частые ошибки

- начать правку без сверки текущего статуса;
- смешать браузер, документацию и Telegram в одном PR;
- повторить опасное действие после неопределённого результата;
- обновить код, но забыть API, пример или тест.

## Завершение

Обновите `PROJECT_STATUS_RU.md` четырьмя фактами: результат, доказательство,
риск, следующий приоритет. Сообщение коммита — понятное и по‑русски. После push
дождитесь CI.
