# Исторические контрольные точки

## Назначение

Это замороженные снимки прошлых этапов. Они помогают расследовать старое
решение, но не описывают текущие возможности.

## Правила

- существующий checkpoint не переписывайте ради актуализации;
- новый создавайте только для важного воспроизводимого рубежа;
- дату, commit SHA, команды проверки и ограничения указывайте явно;
- секреты и runtime-пути не сохраняйте.

Текущий статус всегда берите из `docs/PROJECT_STATUS_RU.md`. Частая ошибка —
перенести старый backlog в новый план без сверки с кодом.

После новой контрольной точки добавьте краткую запись в `CHANGELOG.md`, но не
копируйте туда полный отчёт.
