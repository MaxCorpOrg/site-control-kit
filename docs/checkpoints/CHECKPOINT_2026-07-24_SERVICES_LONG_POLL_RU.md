## Что сохранено

- HTTP-маршруты браузерного контура работают через `HubServices`;
- выделены сервисы команд, клиентов, сессий и состояния;
- `CommandService` атомарно ждёт появления команды;
- прежний немедленный запрос следующей команды остаётся совместимым;
- протокол `2.1` поддерживает необязательный `wait_ms` до 25 секунд;
- расширение `0.3.0` держит один долгий запрос и сразу начинает следующий;
- транспортная политика расширения вынесена в `extension/transport.js`;
- сквозной тест в реальном Chrome измеряет переход команды из очереди
  (`queued`) в аренду исполнителю (`leased`).

## Известные ограничения

- значительная часть прикладной логики физически остаётся в
  `webcontrol/store.py`;
- `extension/background.js` всё ещё совмещает маршрутизацию вкладок, CDP
  (протокол управления Chrome) и очередь результатов;
- каждый долгий запрос занимает один поток встроенного HTTP-сервера;
- HAR (журнал сетевых запросов), трассировка, видео, прокси и управляемые
  профили ещё не реализованы;
- второй браузерный адаптер, Python SDK (набор функций для программного
  доступа) и MCP (протокол подключения инструментов к агентам) пока
  отсутствуют.

```bash
git pull --ff-only
PYTHONPATH="$PWD" python3 -m unittest discover -s tests -p 'test_*.py'

python3 scripts/check_docs.py --base codex/browser-platform-docs-ru
python3 scripts/check_repository.py --base codex/browser-platform-docs-ru
```

Следующий технический шаг: вынести `PolicyEngine` и `StateRepository` за
готовые сервисные интерфейсы без изменения публичного API. После этого
разделить `TabRouter`, `CdpAdapter` и `ResultOutbox` в расширении.

контрольную точку не входят.
