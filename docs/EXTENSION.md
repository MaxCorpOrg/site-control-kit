# Расширение браузера (внутреннее устройство)

## Файлы
- `manifest.json` — манифест, разрешения, точки входа.
- `background.js` — сигнал активности, опрос, маршрутизация команд, отправка результатов.
- `agent_dom.js` — семантический снимок, ссылки, разрешение локаторов и готовность элементов.
- `content.js` — выполнение команд над DOM.
- `options.*` — страница настроек.
- `popup.*` — оперативная диагностика и ручные кнопки (`Опросить сейчас`, `Heartbeat`).

## Пути выполнения

## 1) Команды, выполняемые в фоне
- `navigate`
- `new_tab`
- `reload`
- `activate_tab`
- `close_tab`
- `screenshot`

`screenshot` использует `Page.captureScreenshot` для явно выбранной вкладки,
включая фоновую. `chrome.tabs.captureVisibleTab` остаётся запасным путём
только для активной вкладки. Поле `full_page=true` включает снимок всего
документа.

## 2) Команды через сценарий страницы
`background` отправляет сообщение во вкладку:
```js
{ type: "site-control-command", command: { ... } }
```

`content.js` отвечает:
```js
{ ok: true, data: {...} }
```
или
```js
{ ok: false, error: {...} }
```

Ключевые DOM-команды:
- `click`, `click_text`, `fill`, `focus`
- `snapshot`, `smart_click`, `set_editable_text`, `wait_for`
- `click_menu_text` — клик по видимому пункту меню по тексту
- `extract_text`, `get_html`, `get_attribute`, `get_page_url`
- `wait_selector`, `scroll`, `scroll_by`
- `back`, `forward`, `press_key`, `run_script`

## Логика выбора вкладки
1. `target.tab_id`
2. `target.url_pattern`
3. активная вкладка текущего окна
4. первая доступная вкладка

## Режимы опроса
- Частый `setInterval`.
- Резервный `chrome.alarms` на случай «засыпания» фонового процесса.
- Взаимоисключение не допускает одновременный опрос из интервала, будильника и всплывающего окна.

## Что хранится в `chrome.storage.local`
- `serverUrl`
- `token`
- `clientId`
- `pollIntervalMs`
- `heartbeatIntervalMs`
- служебные поля диагностики (`lastPollAt`, `lastHeartbeatAt`, `lastCommand...`)
- `pendingCommandResults` — долговечная очередь выполненных результатов

Перед получением следующей команды расширение пытается полностью отправить
очередь. Постоянная ошибка HTTP 400/404 означает, что результат больше нельзя принять
(например, хаб не знает команду после сброса состояния); такой потерянный результат фиксируется
в `lastOrphanedCommandResult` и не блокирует очередь.

## DOM-слой для агента

`agent_dom.js` загружается до `content.js` и предоставляет:

- семантический снимок со ссылками;
- строгие локаторы по CSS, ссылке, роли, тексту, подписи, заполнителю и `test-id`;
- открытые Shadow DOM;
- уникальное восстановление ссылки после повторной отрисовки;
- состояния ожидания и готовность элемента.

Схема версии 1 сознательно ограничена верхним фреймом. Реализация доступного имени
покрывает практичные `aria-label`, `aria-labelledby`, labels, alt/title,
button value и visible text, но не заявляет полную W3C ACCNAME совместимость.

Оба сценария страницы защищены от опасной повторной автоматической вставки.

## Метаданные сигнала активности
В сигнале активности расширение отправляет не только `extension_version`, но и `meta.capabilities`:
- `background_commands` — что умеет фоновый процесс без сценария страницы;
- `content_commands` — что умеет DOM-слой.

Это нужно для диагностики устаревшей среды: браузер может работать на старой загруженной версии расширения, когда код в репозитории уже изменился.

## Ограничения MV3
- Фоновый процесс непостоянный.
- На страницах `chrome://*` и ряде служебных URL сценарий страницы не работает.
- Некоторые сайты блокируют `run_script` через CSP (`unsafe-eval` запрещён).

## Замечание по `click_text`
`click_text` ищет текст не только на parent menu-item, но и на вложенных text-span узлах, а затем поднимается к ближайшему кликабельному предку.
Это важно для Telegram Web и похожих UI, где видимый текст лежит в `.btn-menu-item-text`, а кликабельный контейнер — выше по DOM.

## Когда использовать `click_menu_text`
Для всплывающих меню и контекстных меню лучше использовать `click_menu_text`, а не общий `click_text`.
Он ищет только по видимым menu-root контейнерам и лучше подходит для Telegram menu items после `context_click`.

## Как добавить новую команду
1. Обновить схему/описание в `docs/API.md`.
2. Семантику локатора, наблюдения и готовности реализовать в `agent_dom.js`;
   маршрутизацию DOM — в `content.js`; вкладку, CDP и транспорт — в `background.js`.
3. Сохранить единый формат ошибок (`message`, опционально `stack`/`hint`).
4. Добавить пример данных команды в `examples/`.
