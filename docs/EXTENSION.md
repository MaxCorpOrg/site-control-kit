# Расширение браузера: устройство и ограничения

Версия расширения: `0.3.0`.

Расширение Manifest V3 исполняет команды хаба в реальном Chrome или Chromium.
Manifest V3 — текущий формат расширений Chrome с непостоянным фоновым
процессом service worker.

## Файлы

- `manifest.json` — разрешения и точки входа;
- `background.js` — heartbeat, аренда команд, вкладки, фреймы, CDP и отправка
  результатов;
- `transport.js` — построение долгого запроса и задержка повторного соединения;
- `agent_dom.js` — семантические локаторы, снимки, ожидания и восстановление
  ссылок;
- `content.js` — действия внутри документа и совместимые старые команды;
- `options.*` — адрес, токен, время долгого запроса и задержка после ошибки;
- `popup.*` — краткая диагностика и ручной опрос.

`agent_dom.js` загружается раньше `content.js` во всех доступных фреймах.
Повторная инъекция безопасна: оба файла защищены от регистрации второго
обработчика.

## Цикл доставки

Фоновый процесс не запускает два запроса команд одновременно. Один цикл:

1. открывает `GET /api/commands/next?...&wait_ms=25000`;
2. получает аренду сразу после появления команды;
3. подтверждает её через `POST .../ack`;
4. переводит доставку в `running`;
5. исполняет команду;
6. сначала сохраняет результат в локальный outbox — очередь неотправленных
   результатов;
7. отправляет результат хабу;
8. удаляет запись из outbox только после успешного ответа;
9. сразу открывает следующий долгий запрос.

Обычный успешный цикл не использует паузу. `pollIntervalMs` сохранён ради
совместимости настроек, но теперь это задержка повторного соединения после
ошибки. `longPollWaitMs` ограничен диапазоном 1–25 секунд. Таймеры и
`chrome.alarms` остаются резервом пробуждения MV3 service worker.

Outbox хранится в `chrome.storage.local`. После сна или падения service worker
неотправленные результаты продолжают отправляться. Ответы `400`, `404`, `409`
и `410` означают, что аренда уже непригодна; результат удаляется из очереди,
а краткое свидетельство сохраняется как orphaned result — осиротевший
результат.

Пробуждение обеспечивают обычные таймеры и `chrome.alarms`.

## Маршрутизация

Порядок выбора вкладки для старого API:

1. точный `target.tab_id`;
2. `target.url_pattern`;
3. активная вкладка;
4. первая доступная вкладка.

Для сессионных команд хаб требует точные `client_id` и `tab_id`, поэтому
неявный выбор не применяется.

Порядок выбора фрейма:

1. `locator.frame_id` или `command.frame.frame_id`;
2. ссылка `ref` вида `f12:e4`;
3. подстрока URL;
4. имя фрейма;
5. CSS-селектор элемента `iframe` в родителе.

Для снимка расширение получает список фреймов через `chrome.webNavigation`,
запрашивает каждый доступный документ и объединяет элементы. Локальный `e4`
превращается в глобальный `f12:e4`.

## Семантический слой

Снимок не копирует весь HTML. Он оставляет доступные для агента признаки:
роль, имя, значение, `placeholder`, тестовый идентификатор, видимость,
доступность и редактируемость.

Поиск элемента строгий:

- ноль совпадений — `no_match`;
- несколько совпадений — `ambiguous_match`;
- несуществующий `ref` — `unknown_ref`;
- неоднозначное восстановление — `ref_healing_failed`.

Ошибка содержит число и краткий список кандидатов. Автоматический выбор
первого совпадения запрещён.

Перед действием `waitFor` проверяет нужное состояние. Для клика это:
присутствие в DOM, видимость, доступность, стабильная геометрия и попадание
события в элемент.

Открытые Shadow DOM обходятся рекурсивно. Закрытые Shadow DOM не доступны.

## Background-команды

В `background.js` выполняются:

- `navigate`;
- `new_tab`;
- `reload`;
- `activate_tab`;
- `close_tab`;
- `screenshot`;
- `set_file_input_files`.

Полноразмерный снимок использует CDP. Подключение к вкладке сериализовано:
одновременно работает только одна CDP‑операция на вкладку, а `detach`
выполняется в `finally`, даже при ошибке.

## DOM-команды

Новый агентный слой:

- `snapshot`;
- `smart_click`;
- `set_editable_text`;
- `wait_for`;
- `wait_page_state`;
- `describe_frame`;
- `describe_frame_element`.

Совместимый слой:

- `click`, `context_click`, `click_text`, `click_menu_text`;
- `clear_editable`, `fill`, `focus`, `upload_file`;
- `extract_text`, `get_html`, `get_attribute`, `get_page_url`;
- `wait_selector`, `scroll`, `scroll_by`, `wheel`;
- `back`, `forward`, `press_key`, `run_script`;
- `telegram_sticky_author`.

## Диагностика

При ошибке расширение может собрать:

- текущую вкладку и URL;
- семантический снимок;
- кандидатов локатора;
- снимок экрана;
- хвост консоли;
- сетевые ошибки.

Снимок экрана, консоль и сеть включаются политикой сессии. Консоль и сеть
требуют `allow_cdp: true`. Хаб маскирует токены, cookies, пароли, номера карт
и явно перечисленные секреты перед записью артефактов.

## Что хранится локально

- `serverUrl`;
- `token`;
- `clientId`;
- интервал heartbeat, время долгого запроса и задержку после ошибки;
- постоянный outbox результатов;
- время и итог последнего опроса, heartbeat и команды;
- краткие сведения об осиротевших результатах.

Токен никогда не выводится в обычную диагностику.

## Как добавить команду

1. Определить, относится она к браузеру/вкладке или к DOM.
2. Добавить обработчик в `background.js` либо `content.js`.
3. Для DOM‑поиска использовать `agent_dom.js`, не создавать второй механизм
   локаторов.
4. Указать класс команды и политику повтора в `webcontrol/protocol.py`.
5. Добавить пример в `examples/`.
6. Добавить модульный тест и, если команда проходит через браузер, E2E.
7. Обновить [API](API.md).

## Ограничения

- service worker может остановиться в любой момент;
- content script не работает на `chrome://*` и части служебных URL;
- доступ к кросс-доменному iframe зависит от `host_permissions`;
- CSP сайта может запретить `run_script`;
- закрытый Shadow DOM требует отдельного CDP‑адаптера;
- обычный пользовательский Google Chrome новых версий может игнорировать
  загрузку unpacked‑расширения из командной строки; для CI используется
  официальный Chrome for Testing.
