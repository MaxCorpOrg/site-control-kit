# Доступ к браузеру на сервере

Этот сценарий нужен, когда Chrome работает на Linux‑сервере, а оператор хочет
видеть окно удалённо через noVNC.

## Риски

noVNC показывает рабочий стол и может дать контроль над авторизованным
браузером. Не публикуйте порт в интернет без VPN, firewall и отдельной
аутентификации.

## Запуск

```bash
scripts/start_browser_novnc.sh
```

Скрипт поднимает виртуальный X11‑экран, оконный менеджер, браузер, VNC и
веб‑клиент noVNC. Точные порты выводятся в терминал.

Ожидаемый результат: процессы запущены, а локальный URL noVNC открывает
рабочий стол.

Частая ошибка: порт занят. Остановите старый контур или задайте другой порт
поддерживаемым параметром скрипта.

## Проверка хаба

```bash
sitectl health
sitectl browser status
sitectl browser tabs
```

Если расширение не появилось, сравните его адрес и токен с хабом и нажмите
Heartbeat в popup.

## Управление

```bash
sitectl browser open https://example.com
sitectl browser snapshot
sitectl browser smart-click --role link --name "More information..." --exact
```

Используйте точный `--client-id` и `--tab-id`, если подключено несколько
браузеров.

## Остановка

```bash
scripts/stop_browser_novnc.sh
```

После остановки убедитесь, что порты VNC/noVNC больше не слушают сеть.

## Восстановление расширения

Для unpacked‑расширения:

```bash
scripts/reload_bridge_extension.sh
```

После перезагрузки обязательно снова проверьте `browser status`.

## Ограничения

- `chrome://*` не управляется content script;
- обычный пользовательский профиль нельзя копировать или публиковать;
- X11‑fallback использует координаты и менее надёжен, чем DOM‑команды;
- noVNC — операторская диагностика, а не замена автоматическому E2E.
