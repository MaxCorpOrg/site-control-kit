# Диагностика проблем

## Универсальная первая проверка

```bash
sitectl health
sitectl browser status
sitectl browser clients
sitectl browser tabs
```

Если `sitectl` не установлен:

```bash
PYTHONPATH="$PWD" python3 -m webcontrol health
PYTHONPATH="$PWD" python3 -m webcontrol browser status
```

Не начинайте с перезагрузки всего окружения: сначала определите слой сбоя.

## Хаб не запускается

Признак: `Address already in use`.

Причина: порт занят другим хабом или процессом.

Что делать:

1. Проверьте, не отвечает ли уже `sitectl health`.
2. Найдите процесс, слушающий `127.0.0.1:8765`.
3. Штатно остановите ненужный хаб.

Не запускайте два хаба с одной SQLite.

## `401 unauthorized`

Хаб и клиент используют разные токены.

Проверьте источник настройки:

```bash
python3 -m webcontrol runtime-env --format json --no-create
```

Токен в URL или JSON намеренно запрещён. Передавайте его заголовком или через
`SITECTL_TOKEN`.

## `origin_denied`

Запрос пришёл с `Origin`, которого нет в `allowed_origins`.

Не включайте `*`. Добавьте только конкретный доверенный источник в конфигурацию
хаба.

## Расширение не появляется в `clients`

Проверьте:

1. хаб запущен;
2. адрес в options расширения совпадает с адресом хаба;
3. токен совпадает;
4. расширение включено;
5. в popup нажаты `Heartbeat` и `Опросить сейчас`.

После перезагрузки расширения снова выполните `browser status`.

Для автоматического E2E используйте Chrome for Testing. Обычный брендированный
Chrome новых версий может игнорировать `--load-extension`.

## Команда остаётся в `queued`

Возможные причины:

- нет онлайн‑клиента;
- задан неверный `client_id`;
- расширение не выполняет polling;
- target неоднозначен.

Посмотрите карточку команды и очередь клиента:

```bash
sitectl state
sitectl browser clients
```

## Команда в `leased` или `acknowledged`

`leased` без ack означает, что расширение не подтвердило получение.
`acknowledged` без `running` означает, что действие ещё не началось.

После истечения аренды безопасная политика может выдать команду повторно.
`retry_if_not_started` допускает повтор только до `running`.

## `stale_lease`

Результат относится к старой попытке. Хаб уже выдал новую аренду и правильно
отказался принимать старый токен.

Не исправляйте это отключением проверки. Найдите, почему клиент отправлял
результат слишком поздно.

## `dead_letter`

Исход опасной команды неизвестен. Она дошла до `running`, но подтверждённый
результат не получен.

Что делать:

1. отдельной read‑only командой проверить URL, текст или состояние формы;
2. решить, выполнено ли действие;
3. только после проверки создать новую логическую операцию с новым
   `idempotency_key`.

## `session_conflict`

Вкладка уже заблокирована другой сессией, сессия использует другой клиент или
`shared_read` пытается изменить страницу.

```bash
sitectl session list
sitectl session show <session-id>
```

Не используйте `operator_override` автоматически. Это явный операторский
перехват.

## `session_policy`

Действие запрещено политикой: домен, ввод, загрузка, отправка формы,
скачивание, CDP или подтверждение.

Измените policy при создании новой сессии. Не ослабляйте глобальную проверку
ради одного сайта.

## `ambiguous_match`

Локатор нашёл несколько элементов. Ошибка содержит число и кандидатов.

Уточните:

- доступное имя и `--exact`;
- `--root-selector`;
- `--frame-id`;
- `--nth`, только если позиция действительно часть контракта.

## `unknown_ref` или `ref_healing_failed`

Страница сменилась либо элемент нельзя однозначно восстановить.

Сделайте новый `snapshot`. Не подменяйте ошибку выбором первого кандидата.

## Content script не отвечает

Причины:

- вкладка открыта на `chrome://*`;
- страница не разрешена манифестом;
- вкладка была заменена;
- канал content script потерян.

Background автоматически пробует повторную инъекцию на обычной веб‑странице.
На системной странице используйте операторский резервный путь X11 или откройте
обычный URL.

## Команда не работает внутри iframe

Сделайте `snapshot --include-frames` и возьмите `frame_id`. Флаг браузера
ставится до подкоманды:

```bash
sitectl browser --frame-id 3 smart-click --role button --name "Сохранить" --exact
```

Кросс-доменный iframe доступен только если его URL разрешён
`host_permissions`.

## Shadow DOM

Открытый Shadow DOM поддерживается. Закрытый Shadow DOM обычный JavaScript не
видит. Для него нужен отдельный разрешённый CDP-путь или визуальный резерв,
которого пока нет в стабильном API.

## `run_script` блокируется

Сайт может запрещать `eval` через CSP. Используйте нативную DOM‑команду,
семантический локатор или добавьте специализированное действие.

Не отключайте CSP глобально.

## Полноразмерный снимок или CDP завис

Проверьте:

- у сессии `allow_cdp: true`;
- другая CDP‑операция не держит вкладку;
- `chrome.debugger.detach` выполнился после ошибки.

Перезапустите только расширение после сохранения логов, затем повторите
безопасную команду чтения.

## SQLite или `state.json` выглядят повреждёнными

Источником правды является файл `.sqlite3`, а JSON — зеркало.

1. Остановите хаб.
2. Не редактируйте базу вручную.
3. Сохраните копии SQLite, `-wal`, `-shm` и JSON.
4. Проверьте `sitectl storage journal`.
5. Восстановите согласованный backup.

## Где искать диагностику

Карточка сессии содержит `artifact_dir`. Обычно там есть:

- `commands.jsonl`;
- `events.jsonl`;
- `errors.jsonl`;
- `console.jsonl`;
- `network.jsonl`;
- `failures/<command-id>/`.

Если путь или содержимое публикуется, сначала проверьте отсутствие персональных
данных.

## Telegram‑сценарий

Сначала определите слой: discovery, deep path, history backfill, safe snapshot
или batch. Не делайте вывод по одному `latest_full.txt`. Используйте инструкции
папки `scripts/` и архивные handoff‑материалы только после проверки текущего
кода.
