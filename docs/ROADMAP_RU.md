# Дорожная карта развития

Приоритеты построены так, чтобы сначала уменьшить риск потери или двойного
действия, затем расширять возможности.

## Уже закрыто

| Блок | Приоритет | Результат |
| --- | --- | --- |
| Чистая ветка и разделение PR | P0 | PR‑A содержит только браузерное ядро |
| Аренда, ack и повторная выдача | P0 | Потерянных подтверждённых команд в E2E — 0 |
| Идемпотентность и stale lease | P0 | Старый результат отклоняется |
| Сессии и блокировки | P0 | Два агента не меняют одну вкладку |
| Chrome E2E и CI | P0 | 16/16 живых сценариев |
| iframe, Shadow DOM, умные ожидания | P1 | Динамический стенд проходит |
| Failure bundle и редактирование секретов | P1 | Ошибка оставляет безопасные доказательства |

## P1 — следующий цикл

| Работа | Сложность | Зависимости | Ожидаемый эффект |
| --- | --- | --- | --- |
| Разделить `store.py` на сервисы и репозиторий | Высокая | Текущие тесты протокола | Новая политика или backend без переписывания очереди |
| Разделить `background.js` на адаптеры | Высокая | E2E расширения | Изолированные вкладки, фреймы, CDP и outbox |
| Long polling или событийный канал | Средняя | Стабильная аренда | Медианная задержка команды менее 300 мс в локальной сети |
| Управляемый реестр вкладок и метки | Средняя | Сессии | Устойчивые ссылки на вкладки после открытия/закрытия |
| Диалоги, всплывающие окна и скачивания | Средняя | `TabRouter` | Меньше ручных вмешательств |
| Изолированные профили и storage state | Высокая | PolicyEngine | Повторное использование авторизации без обычного профиля |
| Прокси HTTP/SOCKS на сессию | Средняя | BrowserAdapter | Разные сетевые контуры без глобальных флагов |
| Ограничение размера запросов и квоты артефактов | Низкая | ArtifactSink | Защита диска и памяти от неограниченных данных |

| Работа | Сложность | Зависимости | Ожидаемый эффект |

## Порядок архитектурного рефакторинга

1. Добавить интерфейсы рядом с текущим кодом.
2. Завернуть существующее поведение в адаптеры без изменения API.
3. Перенести по одному классу команд.
4. После каждого шага запускать 352+ unit‑теста и Chrome E2E.
5. Только после совпадения поведения удалять старую ветку кода.

Большой «переписать всё» PR запрещён.

## Метрики успеха

- потерянные подтверждённые команды: 0;
- повторные опасные действия: 0;
- зависшие блокировки после TTL: 0;
- локальная p50 доставки: менее 300 мс после long polling;
- p95 безопасной DOM‑команды: менее 2 с на тестовом стенде;
- успешность стандартного E2E: не ниже 99% на 100 последовательных прогонах;
- новый браузерный движок добавляется без изменения `CommandService`;
- пользователь проходит первый сценарий только по `USER_GUIDE_RU.md`.
