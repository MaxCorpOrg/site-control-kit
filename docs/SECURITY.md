# Безопасность

## Модель доверия

Site Control Kit рассчитан на локальную машину или защищённую частную сеть.
Клиент с действующим токеном может управлять браузером от имени пользователя.
Поэтому токен и CDP‑адрес равны по чувствительности паролю.

## Токен хаба

- передавайте токен только через `X-Access-Token` или
  `Authorization: Bearer`;
- не помещайте его в URL, query string — строку параметров, JSON, логи и
  скриншоты;
- используйте длинное случайное значение;
- разные среды должны иметь разные токены;
- при подозрении на утечку остановите хаб и смените токен.

Хаб отклоняет токены в URL и теле запроса. CORS не использует `*`: разрешены
только локальные и extension‑источники из конфигурации.

## Политика сессии

Для автоматизации с изменениями создавайте сессию и задавайте:

- `allowed_domains`;
- `denied_domains`;
- `read_only`;
- `allow_input`;
- `allow_file_upload`;
- `allow_form_submit`;
- `allow_download`;
- `allow_cdp`;
- `max_tabs`;
- `max_session_duration_seconds`;
- `require_dangerous_confirmation`.

Чем уже policy — политика — тем меньше ущерб при ошибке агента.

## Опасные действия

Клики, отправка форм, закрытие вкладки, загрузка файла и произвольный скрипт
не должны автоматически повторяться после `running`. Если результат неизвестен,
проверьте постусловие отдельной командой чтения.

Для чувствительного действия передавайте:

```json
{
  "confirmation": {
    "confirmed": true,
    "reason": "что именно подтвердил оператор"
  }
}
```

Подтверждение не заменяет ограничения домена и владение вкладкой.

## CDP

CDP — Chrome DevTools Protocol — даёт глубокий доступ к вкладке, сети и
файлам. Он выключен по умолчанию.

Правила:

- включайте `allow_cdp` только на время нужной сессии;
- не публикуйте remote debugging port в общую сеть;
- всегда отсоединяйте debugger в `finally`;
- сериализуйте CDP‑операции одной вкладки;
- не подключайтесь к обычному профилю пользователя без явного согласия;
- маскируйте заголовки `Authorization`, `Cookie` и тела запросов.

## Профили и авторизация сайтов

Профиль браузера содержит cookies, IndexedDB, localStorage и токены сессии.
Его нельзя коммитить или передавать как обычный архив.

Текущая браузерная платформа использует уже открытый пользовательский браузер.
Изолированное сохранение и шифрование профилей запланировано, но ещё не
считается готовой возможностью.

## Артефакты

Хаб маскирует:

- поля `token`, `password`, `authorization`, `cookie` и похожие;
- Bearer‑токены;
- номера платёжных карт;
- явно указанные `policy.secrets`.

Маскирование снижает риск, но не доказывает отсутствие любых персональных
данных в тексте страницы. Перед передачей failure bundle проверьте его вручную.

Сырые артефакты должны иметь ограниченный срок хранения и минимальные права
доступа.

## Загрузка и скачивание файлов

Загрузка и скачивание запрещены policy по умолчанию. Разрешайте только
конкретный сценарий и проверенный каталог.

Нельзя:

- передавать путь вне разрешённой рабочей области;
- автоматически открывать скачанный исполняемый файл;
- считать имя файла доказательством его типа;
- сохранять файл поверх важного существующего пути.

## Документация и Git

Перед коммитом выполняйте:

```bash
python3 scripts/check_repository.py --base origin/main
python3 scripts/check_docs.py
```

Проверка ищет секреты, закрытые ключи, публичные IP, приватные абсолютные пути,
runtime‑каталоги, бинарные файлы и рассинхронизацию версий.

## Сообщение об уязвимости

Не публикуйте рабочий токен, профиль или персональные данные в GitHub Issue.
Передайте минимальное воспроизведение владельцу репозитория по закрытому
каналу, опишите версию, входные условия и ожидаемый ущерб.

## Правовое использование

Автоматизируйте только ресурсы и учётные записи, которыми имеете право
управлять. Уважайте правила сайта, согласие пользователя, ограничения доступа
и применимое законодательство.
