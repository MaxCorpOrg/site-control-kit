# Словарь технических терминов

Документация проекта написана по-русски. Английские слова оставляются только там, где это имя продукта, команда, путь, ключ протокола или общепринятый технический термин. При первом знакомстве с проектом используйте этот словарь.

| Термин | Что означает в проекте |
|---|---|
| API | Программный интерфейс: набор HTTP-адресов, команд и форматов данных. |
| CLI | Интерфейс командной строки. В проекте это прежде всего `sitectl`. |
| hub, хаб | Локальный узел управления, который хранит клиентов, команды и результаты. |
| bridge, мост | Связь между хабом и расширением браузера. |
| browser agent | ИИ-агент, который управляет браузером через стабильный программный контракт. |
| DOM | Объектная модель документа: программное представление элементов страницы. |
| locator, локатор | Описание способа найти элемент: по роли, тексту, подписи, CSS-селектору или ссылке `ref`. |
| `ref` | Короткая ссылка на элемент из снимка страницы. Действует только для текущего состояния страницы. |
| snapshot, снимок | Компактное структурированное описание видимых и интерактивных элементов страницы. |
| actionability, готовность к действию | Проверка, что элемент существует, видим, не заблокирован и с ним можно взаимодействовать. |
| smart wait, умное ожидание | Ожидание нужного состояния страницы или элемента вместо фиксированной паузы. |
| healing, восстановление локатора | Повторный поиск элемента другим способом, если исходная ссылка устарела. |
| heartbeat, сигнал активности | Периодическое сообщение расширения, подтверждающее, что клиент жив. |
| polling, периодический опрос | Регулярный запрос расширения к хабу за новой командой. |
| outbox, очередь отправки | Локальная очередь результатов, которые ещё не удалось передать хабу. |
| lease, аренда доставки | Ограниченное по времени право клиента выполнить конкретную команду. |
| acknowledgement, подтверждение | Явное подтверждение получения команды; сокращённо часто пишется `ack`. |
| retry, повтор | Новая попытка той же операции после временной ошибки. |
| fallback, запасной путь | Альтернативный способ выполнить действие, когда основной не сработал. |
| smoke test, быстрая проверка | Короткий сценарий, подтверждающий работу основного контура. |
| live-проверка | Проверка на реально запущенном хабе, расширении и браузере. |
| end-to-end, сквозная проверка | Проверка полного пути от команды агента до результата браузера. |
| runtime, среда выполнения | Запущенные процессы и их рабочие файлы: состояние, журналы и временные данные. |
| artifact, артефакт | Файл с доказательством или результатом запуска: журнал, снимок, отчёт, видео. |
| workflow, рабочий сценарий | Последовательность связанных действий инструмента. |
| job, задание | Один сохраняемый запуск рабочего сценария с состоянием и артефактами. |
| profile, профиль | Изолированный набор настроек и данных конкретного пользователя или браузера. |
| manifest, манифест | Файл с описанием инструмента, его команд и возможностей. |
| registry, реестр | Список подключённых инструментов и их манифестов. |
| driver, драйвер | Сменный модуль, который реализует управление конкретным браузерным движком. |
| proxy, прокси | Промежуточный сетевой сервер для выбранного профиля или браузера. |
| trace, трассировка | Последовательная запись команд, событий и результатов для диагностики. |
| replay, воспроизведение | Повтор или разбор ранее записанного сценария. |
| headless, без интерфейса | Запуск браузера без видимого окна. |
| multi-engine, несколько движков | Поддержка Chromium, Firefox и WebKit через общий интерфейс. |
| CDP | Протокол разработчика Chrome, используемый для снимков экрана и низкоуровневого управления Chromium. |
| MV3 | Третья версия формата расширений Chromium. |
| CSP | Политика безопасности страницы, которая может запрещать выполнение внедрённого JavaScript-кода. |
| X11 | Оконная система Linux, используемая как запасной путь для кликов и клавиш. |
| noVNC | Доступ к экрану браузера через веб-интерфейс VNC. |
| P0, P1, P2, P3 | Уровни приоритета: от обязательного и срочного P0 до перспективного P3. |

Имена команд (`smart-click`), типы протокола (`smart_click`), ключи JSON (`client_id`), пути и имена файлов не переводятся: иначе документация перестанет совпадать с кодом.
