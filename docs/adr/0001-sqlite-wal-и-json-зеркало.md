# ADR-0001: SQLite WAL как источник правды

- Статус: принято
- Дата: 2026-07-24
- Область: хаб и хранение состояния

## Контекст

Раньше хаб перезаписывал один `state.json`. При аварии между открытием файла и
записью можно было потерять состояние очередей. Формат также не давал
транзакционного журнала, согласованной резервной копии и безопасного развития
схемы.

## Решение

Использовать SQLite в режиме WAL — журнал предзаписи — как источник правды.
Хранить:

- версию схемы;
- одно согласованное состояние хаба;
- добавочный журнал переходов.

После транзакции обновлять `state.json` атомарной заменой. JSON остаётся
диагностическим зеркалом и форматом миграции, но не участвует в разрешении
конкурирующих записей.

При первом запуске существующий JSON импортируется в SQLite, а перед миграцией
сохраняется его резервная копия. Резервная копия рабочей базы делается штатным
SQLite backup API.

## Последствия

Плюсы:

- команда, аренда и результат сохраняются транзакционно;
- после падения хаб поднимает последнее подтверждённое состояние;
- журнал помогает разбирать гонки и повторы;
- формат можно мигрировать по версии.

Ограничение: текущий процессный хаб остаётся единственным писателем. Запускать
два хаба на одной базе нельзя; распределённое хранение в это решение не входит.
