# ADR-0002: Аренда команд, ack и идемпотентность

- Статус: принято
- Дата: 2026-07-24
- Область: протокол доставки

## Контекст

Простой `GET next -> выполнить -> POST result` не различает потерянный ответ,
падение расширения до начала действия и падение после клика. Слепой повтор
может дважды отправить форму или нажать опасную кнопку.

## Решение

Ввести явные состояния `queued`, `leased`, `acknowledged`, `running` и
терминальные состояния. Каждая попытка получает новый `lease_token`, а
доставка сохраняет постоянный `delivery_id`.

Расширение обязано:

1. получить аренду;
2. отправить ack — подтверждение получения;
3. сообщить `running`;
4. сохранить результат в локальный outbox;
5. отправлять сохранённый результат до подтверждения хаба.

Хаб принимает результат только текущей аренды. Полностью одинаковый повтор
результата допустим, противоречащий результат — конфликт.

Политика повтора задаётся отдельно для команды. Опасное действие после
`running` автоматически не повторяется и попадает в `dead_letter`.

Ключ `idempotency_key` не даёт агенту поставить одну логическую операцию два
раза.

## Последствия

Гарантия соответствует at-least-once delivery — доставке не менее одного раза,
— но не обещает невозможного exactly-once исполнения внешнего сайта. Риск
двойного опасного действия снимается запретом слепого повтора и проверкой
постусловий.
