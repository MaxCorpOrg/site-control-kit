# Архитектурные решения

## Назначение

Каждый ADR — короткая запись одного принятого архитектурного решения.

## Как добавить решение

Укажите проблему, рассмотренные варианты, выбор, причины, последствия и способ
отката. Номер не переиспользуйте. Старое решение не переписывайте задним
числом: добавьте новый ADR со ссылкой на заменённый.

Не помещайте сюда пользовательские команды и журнал работы. После изменения
сверьте `docs/ARCHITECTURE.md`.

## Проверка и частые ошибки

Запустите `python3 scripts/check_docs.py`. Частая ошибка — переписать старое
решение вместо нового ADR или не указать реальный способ отката.

Связанные документы: `docs/ARCHITECTURE.md`, `docs/API.md` и
`docs/ROADMAP_RU.md`. Обновляйте только те из них, чей контракт реально
изменился.
