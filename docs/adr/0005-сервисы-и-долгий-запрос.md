# ADR-0005: сервисные границы и долгий запрос команд

## Проблема

HTTP-маршруты напрямую вызывали большой `ControlStore`, а расширение делало
новый запрос раз в две секунды. Из-за этого транспорт, доменные переходы и
хранилище были связаны, а новая команда могла ждать следующего опроса.

## Варианты

1. Оставить частый опрос и уменьшить интервал.
2. Добавить WebSocket.
3. Добавить совместимый долгий HTTP-запрос и сервисную границу над store.

Частый опрос создаёт лишние запросы и всё равно оставляет задержку. WebSocket
требует отдельного сервера, протокола восстановления и более крупного
изменения MV3-контура.

## Решение

Принят вариант 3:

- `HubServices` отделяет HTTP от команд, клиентов, сессий и состояния;
- `CommandService` атомарно проверяет очередь и ждёт уведомление;
- `POST /api/commands` уведомляет ожидающие запросы только после успешной
  транзакции store;
- `GET /api/commands/next` принимает `wait_ms`, максимум 25 секунд;
- отсутствие `wait_ms` сохраняет немедленный режим старого клиента;
- расширение держит один запрос, после ответа сразу открывает следующий;
- `transport.js` содержит чистые правила URL, ограничений и задержки ошибки.

Состояние ожидания не сохраняется. Источником правды остаётся SQLite, а после
перезапуска расширение открывает новый запрос.

## Последствия

Плюсы:

- новая команда будит клиент без ожидания двухсекундного таймера;
- HTTP можно тестировать через интерфейс сервиса;
- дальнейший перенос логики из `store.py` не меняет маршруты;
- старое расширение продолжает работать.

Ограничения:

- один долгий запрос занимает один поток локального HTTP-сервера;
- текущая реализация рассчитана на локальное число клиентов;
- `PolicyEngine`, `StateRepository`, вкладки, CDP и outbox ещё не выделены;
- постановка команды в обход `CommandService` не отправит уведомление.

## Откат

Вернуть расширение `0.2.0` или вызывать маршрут без `wait_ms`: сервер сохранит
немедленный ответ. `HubServices` можно заменить прямым адаптером store без
миграции SQLite и изменения формата команды.
