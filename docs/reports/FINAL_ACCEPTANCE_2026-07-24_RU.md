## Что изменено

### Надёжность и хранение

- `webcontrol/store.py`, `webcontrol/protocol.py`,
  `webcontrol/state_backend.py` — жизненный цикл команды, аренда, подтверждение
  получения, повторная выдача, политики повторов, идемпотентность, SQLite WAL
  и журнал событий;
- `webcontrol/server.py`, `webcontrol/cli.py` — HTTP API и CLI для нового
  протокола, сессий, блокировок и агентных действий;
- `webcontrol/config.py`, `webcontrol/utils.py` — настройки протокола и
  безопасная обработка данных.

### Агентное управление страницей

- `webcontrol/browser_agent.py` — агентный API, строгие локаторы, ожидания и
  доказательство результата;
- `extension/agent_dom.js` — семантический снимок, восстановление ссылок
  `ref`, открытый Shadow DOM, `iframe` и вложенные фреймы;
- `extension/background.js`, `extension/content.js` — выполнение команд,
  постоянная очередь результатов и восстановление после остановки фонового
  процесса расширения;
- `webcontrol/artifacts.py` — диагностические артефакты и маскирование
  чувствительных значений.

### Проверки

- `.github/workflows/browser-core.yml` — модульные, статические, security- и
  Chrome-проверки;
- `scripts/browser_e2e.py` — сквозной стенд с настоящим Chrome и
  распакованным расширением;
- `scripts/check_repository.py` — запрет секретов, runtime-данных и
  неподходящих бинарных файлов;
- `scripts/check_docs.py` — ссылки, версии, синтаксис CLI и инструкции
  агентов;
- `tests/test_reliable_delivery.py`, `tests/test_agent_sessions.py`,
  `tests/test_browser_agent.py`, `tests/test_server_api.py`,
  `tests/js/agent_dom.test.mjs` — регрессионное покрытие нового контура.

### Документация

- `README.md`, `USER_GUIDE_RU.md`, `BROWSER_QUICKSTART.md` — путь нового
  пользователя;
- `START_HERE_AGENT_RU.md`, `docs/AI_MAINTAINER_GUIDE.md`,

## Архитектурные решения

Решения записаны отдельно, чтобы их можно было пересмотреть без поиска по
истории:

1. [SQLite WAL и JSON-зеркало](../adr/0001-sqlite-wal-и-json-зеркало.md).
2. [Аренда команд и идемпотентность](../adr/0002-аренда-команд-и-идемпотентность.md).
3. [Сессии и блокировки вкладок](../adr/0003-сессии-и-блокировки-вкладок.md).
4. [Семантические локаторы и фреймы](../adr/0004-семантические-локаторы-и-фреймы.md).

Публичный API сохранён обратно совместимым: старые CSS-команды не удалены.
Гарантии протокола `2.0` доступны новым клиентам; старый клиент работает в
режиме совместимости.

## Что сознательно не изменялось

- Telegram export, invite, portable, GUI и упаковка;
- прикладная логика Feishu;
- собранные `.exe`, локальные профили и runtime-артефакты;
- Firefox, WebKit и Playwright-адаптер;
- Python SDK и MCP-интерфейс.

Эти области не нужны для закрытия P0 и не смешиваются с браузерным ядром.

## Остаточные риски и следующий шаг

| Риск | Критичность | Почему не входит сейчас | Следующий шаг и зависимости |
|---|---|---|---|
| Опрос хаба даёт задержку около двух секунд | Средняя | P0 закрывает надёжность, а не транспорт | P1: длинный опрос (long polling) или событийный канал; нужны метрики задержки |
| `store.py` и `background.js` совмещают несколько ролей | Средняя | Большой рефакторинг увеличил бы риск при стабилизации | P1: выделить сервисы и адаптеры под существующими тестами |
| HAR, трассировка и видео пока только поля политики | Средняя | Нужны правила хранения и очистки чувствительных данных | P2: реализовать сбор после отдельной проверки безопасности |
| Нет управляемых профилей, прокси, полного API скачиваний и диалогов | Средняя | Это отдельные контракты и политики безопасности | P1–P2: профили → скачивания/диалоги → прокси |
| Нет Firefox/WebKit и Playwright-адаптера | Низкая для текущего Chrome-контура | P0 должен быть доказан на одном исполнителе | P2–P3: `BrowserAdapter`, затем второй движок |
| Нет Python SDK и MCP | Низкая для CLI/HTTP | Нельзя закреплять SDK поверх нестабильных внутренних границ | P3: после выделения сервисов и стабилизации API |
| Старые клиенты не получают полных гарантий `2.0` | Средняя при смешанном парке | Сохранена обратная совместимость | Обновить расширения, затем объявить срок устаревания режима совместимости |
| Одна SQLite допускает только один пишущий хаб | Низкая для локального режима | Распределённый хаб не входит в цель | При удалённых исполнителях выбрать серверное хранилище и миграцию |

Приоритеты, сложность, зависимости и ожидаемый эффект подробно описаны в
[дорожной карте](../ROADMAP_RU.md).
