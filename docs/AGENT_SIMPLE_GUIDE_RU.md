# Простой путеводитель для агента

Этот файл нужен, чтобы открыть проект и сразу начать работать. Термины объяснены в [словаре](TERMS_RU.md).

## За две минуты

1. Прочитайте `START_HERE_AGENT_RU.md`.
2. Посмотрите конец `docs/PROJECT_STATUS_RU.md`: там последний завершённый блок, текущий риск и следующий шаг.
3. Выполните `git status --short --branch` и не трогайте чужие изменения.
4. Выберите нужный контур по карте ниже.
5. После правки запустите полный набор тестов и обновите статус проекта.

Главное правило: хаб хранит истину о клиентах и командах, расширение исполняет браузерные действия, а командная строка даёт короткий интерфейс человеку и агенту.

## Куда идти с задачей

| Задача | Основные файлы |
|---|---|
| HTTP API, токен, очередь, состояние команды | `webcontrol/server.py`, `webcontrol/store.py` |
| Команда `sitectl browser` | `webcontrol/cli.py` |
| Схема API для агента | `webcontrol/browser_agent.py` |
| Действие с вкладкой или снимок экрана | `extension/background.js` |
| Действие с элементом страницы | `extension/content.js`, `extension/agent_dom.js` |
| Экспорт пользователей Telegram | `scripts/export_telegram_members_non_pii.py` и соседние сценарии |
| Приглашения Telegram | `scripts/telegram_invite_manager.py`, `scripts/telegram_invite_executor.py` |
| Переносимый Telegram Desktop | `scripts/telegram_portable.py` |
| Единая панель и задания | `tool_platform/` |
| Сборка выпуска | `packaging/` |

В каждой рабочей папке есть свой `AGENTS.md` с локальными правилами.

## Быстрый сценарий управления браузером

Сначала проверьте живой контур:

```bash
PYTHONPATH="$PWD" python3 -m webcontrol browser status
PYTHONPATH="$PWD" python3 -m webcontrol browser tabs
```

Откройте страницу и получите снимок:

```bash
PYTHONPATH="$PWD" python3 -m webcontrol browser open https://example.com
PYTHONPATH="$PWD" python3 -m webcontrol browser snapshot
```

Найдите в снимке нужный `ref`, затем действуйте:

```bash
PYTHONPATH="$PWD" python3 -m webcontrol browser smart-click --ref e7
PYTHONPATH="$PWD" python3 -m webcontrol browser set-text "agent@example.com" --label "Электронная почта"
PYTHONPATH="$PWD" python3 -m webcontrol browser wait-for --text "Готово"
```

Если `ref` устарел, сделайте новый снимок или передайте устойчивый локатор по роли, подписи либо тексту. Не добавляйте произвольную задержку, пока можно дождаться наблюдаемого состояния.

## Как добавить браузерную команду

Если команда работает с вкладкой целиком:

1. Реализуйте её в `extension/background.js`.
2. Добавьте возможность в сигнал активности расширения.
3. Добавьте короткую команду в `webcontrol/cli.py`, если она нужна оператору.

Если команда работает с DOM:

1. Общий поиск и ожидания размещайте в `extension/agent_dom.js`.
2. Маршрутизацию команды размещайте в `extension/content.js`.
3. Не дублируйте поиск элементов внутри каждой команды.

Для обеих разновидностей:

1. Обновите `webcontrol/browser_agent.py`.
2. Обновите `docs/API.md`, `docs/EXTENSION.md` и при необходимости `docs/ARCHITECTURE.md`.
3. Добавьте пример в `examples/`.
4. Добавьте тест.

## Как не перепутать Telegram-контуры

- Нужно собрать безопасные `@username` — используйте экспорт, а не приглашения.
- Нужно обработать только согласованных пользователей — используйте менеджер и исполнитель приглашений.
- Есть архив `tdata.zip` — используйте переносимый помощник Telegram Desktop.
- Нужна общая панель, история задания или блокировка профиля — используйте `tool_platform/`.

Не делайте вывод по одному `latest_full.txt`. Смотрите `latest_full.md`, `latest_safe.md`, последний `run.json`, `export.log`, `export_stats.json`, а также `identity_history.json` и `discovery_state.json`.

## Проверки перед завершением

Всегда:

```bash
PYTHONPATH="$PWD" python3 -m unittest discover -s tests -p 'test_*.py'
git diff --check
```

Если менялся Python-код:

```bash
python3 -m py_compile путь/к/изменённому.py
```

Если менялся сценарий оболочки:

```bash
bash -n путь/к/изменённому.sh
```

Если менялось расширение:

```bash
node --check extension/background.js
node --check extension/content.js
node --check extension/agent_dom.js
```

После проверок запишите в `docs/PROJECT_STATUS_RU.md`:

- что сделано;
- чем проверено;
- какой риск остался;
- что делать следующим.

## Частые вопросы

### Хаб не отвечает. Что делать?

Запустите `scripts/start_hub.sh`, затем повторите `browser status`. Проверьте адрес, порт и токен. Не ослабляйте проверку токена.

### Вкладки есть, но команда ушла не туда

Сначала выполните `browser tabs`, затем явно передайте нужный `--client-id` и `--tab-id`. Не полагайтесь на случайную активную вкладку.

### `navigate` работает, а клик нет

На защищённых `chrome://`-страницах сценарий страницы не запускается. На обычной странице проверьте, что расширение внедрило `content.js`, затем сделайте новый снимок.

### Ссылка `ref` больше не находится

Страница изменилась. Получите новый снимок. Для повторяемого сценария используйте роль, подпись, текст, заполнитель или `data-testid`.

### Выполнение JavaScript-кода запрещено

Это может быть CSP сайта. Предпочтите штатную DOM-команду или добавьте новую команду в расширение. Не стройте основной сценарий на `run_script`.

### Где искать причину сбоя?

Начните с результата команды в хабе, затем проверьте диагностические поля расширения и артефакты запуска. Для будущих сценариев используйте один идентификатор команды во всех журналах.

### Можно ли сразу добавить зависимость?

Только если без неё нельзя получить нужную надёжность или поддержку платформы. Сначала зафиксируйте причину, размер зависимости, риски и запасной вариант.

### Что нельзя коммитить?

Локальные сеансы, токены, пользовательские данные, каталоги `runtime/`, `TG_APP/`, `telegram_ak/`, `.codex` и случайные артефакты. Перед коммитом всегда просмотрите точный список файлов.

## Когда работа действительно закончена

Код, тесты, примеры и документация совпадают. Полный набор тестов прошёл. Для живого контура сохранено доказательство проверки. Статус проекта обновлён. В коммит не попали чужие или секретные файлы.
