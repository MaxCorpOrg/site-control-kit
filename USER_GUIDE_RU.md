# Руководство пользователя Site Control Kit

Это пошаговая инструкция для первого запуска. Команды выполняются из корня
репозитория.

## 1. Что делает программа

Программа принимает команду, передаёт её расширению браузера и возвращает
результат. Например, можно открыть страницу, получить список доступных
элементов, нажать кнопку или заполнить поле.

Ваш обычный браузер не заменяется. Управление работает только там, где
установлено и подключено расширение Site Control Kit.

## 2. Что установить

Нужно:

- Python 3.10 или новее;
- Git;
- Google Chrome, Chromium или Microsoft Edge на базе Chromium.

Проверьте Python:

```bash
python3 --version
```

Ожидается строка вроде `Python 3.12.3`.

Частая ошибка: `python3: command not found`.

Исправление: установите Python из пакетного менеджера вашей системы или с
официального сайта Python.

## 3. Установка проекта

```bash
python3 -m pip install -e .
```

Ожидается успешное сообщение `Successfully installed site-control-kit`.

Если система запрещает глобальную установку, создайте отдельное окружение:

```bash
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -e .
```

На Windows команда активации:

```powershell
.\.venv\Scripts\Activate.ps1
```

## 4. Где взять токен

Для первого локального запуска создайте случайный токен и покажите его только
в своём терминале:

```bash
python3 -m webcontrol runtime-env --format json --show-secrets
```

Ожидается JSON с полями:

```json
{
  "SITECTL_TOKEN": "sitectl-длинная-случайная-строка",
  "SITECTL_TOKEN_SOURCE": "generated_token_file"
}
```

Скопируйте значение `SITECTL_TOKEN` в настройки расширения. Не отправляйте
этот вывод в чат, issue или лог.

Для постоянной работы можно задать свой токен:

```bash
export SITECTL_TOKEN="замените-на-длинную-случайную-строку"
```

PowerShell:

```powershell
$env:SITECTL_TOKEN = "замените-на-длинную-случайную-строку"
```

Не вставляйте токен в URL, JSON‑команду, документацию или коммит.

Частая ошибка: в выводе видно `<redacted>` вместо токена.

Исправление: параметр `--show-secrets` используйте только в личном терминале.
Обычный диагностический вывод намеренно скрывает секрет.

## 5. Как запустить хаб

Linux и macOS:

```bash
PYTHONPATH="$PWD" python3 -m webcontrol serve
```

Windows:

```powershell
.\start-hub.cmd
```

Ожидаемый вывод:

```text
Server started on http://127.0.0.1:8765
```

Частая ошибка: порт `8765` уже занят.

Исправление: проверьте, не запущен ли хаб в другом окне. Если да, используйте
его или корректно остановите старый процесс.

## 6. Как установить расширение

1. Откройте `chrome://extensions`.
2. Включите режим разработчика.
3. Нажмите «Загрузить распакованное расширение».
4. Выберите папку `extension`.
5. Откройте настройки расширения.
6. Укажите адрес `http://127.0.0.1:8765` и тот же токен, что у хаба.
7. Оставьте рекомендуемые значения: ожидание команды `25000` мс и задержка
   повтора после ошибки `2000` мс.
8. Сохраните настройки.

Ожидается зелёный статус соединения в popup расширения.

Частая ошибка: расширение установлено, но хаб его не видит.

Исправление: сравните адрес и токен, нажмите в popup «Heartbeat», затем
выполните `sitectl browser status`.

Долгое ожидание не означает задержку команды: запрос завершается сразу, когда
хаб ставит команду в очередь. Значение `25000` ограничивает только время одного
HTTP-запроса.

## 7. Как проверить подключение

```bash
sitectl health
sitectl browser status
sitectl browser clients
sitectl browser tabs
```

Ожидается JSON, где здоровье хаба и клиент отмечены как успешные:

```json
{"ok": true}
```

Если `sitectl` не найден:

```bash
PYTHONPATH="$PWD" python3 -m webcontrol browser status
```

## 8. Как открыть страницу

```bash
sitectl browser open https://example.com
```

Ожидается завершённая команда и вкладка с `example.com`.

Частая ошибка: несколько браузерных клиентов онлайн.

Исправление: посмотрите `sitectl browser clients` и добавьте
`--client-id <id>`.

## 9. Как сделать первый снимок

```bash
sitectl browser snapshot
```

Ожидается JSON с массивом `data.lines`, например:

```json
{
  "ok": true,
  "data": {
    "lines": [
      "[f0:e1] heading \"Example Domain\"",
      "[f0:e2] link \"More information...\""
    ]
  }
}
```

`f0:e2` — короткая ссылка на элемент. Она действует в рамках текущего
документа и может быть восстановлена после безопасной перерисовки DOM.

## 10. Как нажать кнопку или ссылку

По ссылке из снимка:

```bash
sitectl browser smart-click --ref f0:e2
```

По роли и имени:

```bash
sitectl browser smart-click --role button --name "Сохранить" --exact
```

Если найдено несколько элементов, команда остановится и покажет кандидатов.
Уточните имя, корневой селектор или `--nth`.

## 11. Как ввести текст

```bash
sitectl browser set-text --label "Имя" "Анна"
```

Или по `ref`:

```bash
sitectl browser set-text --ref f0:e4 "Анна"
```

Ожидается `changed: true` и подтверждение нового значения.

Частая ошибка: найдено больше одного поля с той же подписью.

Исправление: возьмите точный `ref` из свежего снимка или добавьте
`--root-selector`.

## 12. Безопасная сессия агента

Создайте сессию:

```bash
sitectl session create --owner-id user-guide --ttl-seconds 300
```

Затем заблокируйте вкладку, используя идентификаторы из `browser tabs`:

```bash
sitectl session lock <session-id> --client-id <client-id> --tab-id <tab-id>
```

Закройте сессию после работы:

```bash
sitectl session close <session-id>
```

Если сессия забыта, TTL — срок жизни — освободит блокировку автоматически.

Частая ошибка: `tab_lock_conflict`.

Исправление: не забирайте вкладку у другого агента. Выберите другую вкладку
или явно завершите прежнюю сессию после согласования.

## 13. Что делать при ошибке

Сначала выполните:

```bash
sitectl health
sitectl browser status
sitectl browser tabs
```

Затем откройте [справочник ошибок](docs/TROUBLESHOOTING.md).

При ошибке сессии смотрите каталог артефактов, указанный в её карточке. В нём
есть команды, события, ошибки и, если разрешено, снимок.

Ожидаемый результат диагностики — понятный код ошибки, идентификатор команды и
путь к пакету доказательств. Если этих данных нет, сохраните вывод трёх команд
выше и не повторяйте опасное действие.

## 14. Как остановить программу

В окне хаба нажмите `Ctrl+C`.

На Windows можно закрыть окно `start-hub.cmd`, но `Ctrl+C` лучше: хаб
завершится штатно.

Расширение можно временно отключить на `chrome://extensions`.

## 15. Как обновить

```bash
git pull --ff-only
python3 -m pip install -e .
```

После обновления расширения:

1. откройте `chrome://extensions`;
2. нажмите кнопку перезагрузки Site Control Kit;
3. снова проверьте `sitectl browser status`.

Если обновилась схема хранилища, хаб автоматически сделает миграцию старого
JSON в SQLite. Перед ручными операциями можно выполнить:

```bash
sitectl storage backup
```

Ожидается `ok: true` и путь к файлу `.sqlite3`.

Частая ошибка: `git pull --ff-only` сообщает о локальных изменениях.

Исправление: не удаляйте их вслепую. Выполните `git status --short`, сохраните
свои файлы и только затем обновляйте checkout.

## 16. Как полностью удалить

1. Остановите хаб.
2. Удалите расширение через `chrome://extensions`.
3. Удалите пакет:

```bash
python3 -m pip uninstall site-control-kit
```

4. Если данные больше не нужны, вручную удалите runtime‑каталог, который
показывает:

```bash
python3 -m webcontrol runtime-env --format json --no-create
```

Не удаляйте каталог, пока не сохранили нужные сессии, логи и резервные копии.

Ожидается, что после удаления `sitectl` больше не находится, а расширение
исчезло из списка Chrome.

Частая ошибка: после удаления пакета остались данные.

Это штатно: программа не стирает пользовательские логи автоматически. Удалите
показанный runtime-каталог вручную только после проверки резервной копии.
